THE PASS

Step 1 runs once, before any of this. After that, a pass is the same nine
actions every time.

  1. Sweep segment 3.        -> 03-results-seg3.txt
  2. Sweep segment 1.        -> 03-results-seg1.txt
  3. Sweep segment 2.        -> 03-results-seg2.txt
  4. Sweep segment 4.        -> 03-results-seg4.txt
  5. LinkedIn runs, in this order:
       set 1 toronto, set 1 remote
       set 2 toronto, set 2 remote
       set 4 toronto, set 4 remote
       set 3 toronto, set 3 remote — the two to skip when sessions are
       short; sweep 3 already covers their ground
     Each writes its own 04-linkedin-*.txt. Stop whenever you want.
  6. Triage.                 -> 05-triage.txt, keyword-append-edits.txt,
                                updated ledger.csv
  7. Open keyword-append-edits.txt. NONE: done. Otherwise run Step 4B: it
     patches the 02-linkedin-* files and hands you the lines to append to
     keyword-edits.txt.
  8. Apply to Tier 1. Set each to applied in the ledger as you go.
  9. Read the Tier 3 reasons and set the ones you agree with to skipped.

The ledger stays in the root; everything else a pass writes goes into the run
folder, and triage attaches what the sweeps wrote there.
